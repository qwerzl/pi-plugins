# @qwerzl/pi-auto-title

Short, AI-generated pi session names that stay fixed:

- `🏷️ Auto titles`
- `🔐 Fix login`
- `🧪 Add tests`

## Enable

From this repository after installing its dependencies:

```sh
pi install ./packages/auto-title
```

Restart pi. The local installation loads this checkout directly, so keep it and its dependencies in place. Use `pi remove ./packages/auto-title` from the repo root to disable it for future sessions.

## Behavior

After the first successful completed reply in an unnamed session, the extension asks the active model for one emoji plus 2–5 simple words. Once the session has a name, it makes no further naming requests, even if the topic changes. Titles are capped at 40 grapheme clusters, terminal control sequences are stripped, and a missing emoji gets a `💬` prefix.

At most four recent user/assistant text messages (1,200 characters each) are sent to the same model/provider already selected for the conversation. Tool results, thinking blocks and images are excluded.

The session name is persisted through pi's normal API for `/resume`. The terminal receives just the short emoji title, without pi's usual `π - … - Projects` wrapper; this also lets the cmux Projects sidebar display it rather than falling back to the latest prompt. No separate shell hook is required. Existing unnamed sessions get a title after their next successful reply. Existing names stay fixed after resume/reload, including names generated by earlier versions of the extension.

A manual `/name` takes precedence, including if you rename while a request is in flight. A new reply or session shutdown cancels stale title requests. Failures and the 15-second timeout leave the existing title alone. The extension shows one warning per session load if title generation fails, then tries again after the next completed reply. Canceled requests do not warn. Print/headless runs and aborted or failed replies do not trigger naming.

## Cost and privacy

Naming makes **one extra background request** with no tools, with retries after later completed replies only if the session remains unnamed. Reasoning models use `low` thinking and a 1,024-token output budget, which also covers thinking. This avoids asking reasoning-only models to disable thinking, which some providers reject. Non-reasoning models keep the 64-token output budget with no requested thinking. This does not add messages to the main conversation or change its model/settings. Normal provider billing applies; the extra request's usage is **not added to pi's main conversation token totals**.

Names are visible in terminal tabs and session lists. Although the model is instructed not to include secrets or personal information, that is not a redaction guarantee. Assign a manual generic name before discussing sensitive material if it must not influence the title.
